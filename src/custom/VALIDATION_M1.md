## 매핑 화면 연동 검증

공식 main.py에서 RViz 자동 실행을 확인했다. 화면의 Global Status가 Ok이며 실시간 점유 지도(600×600), LiDAR 스캔, 골반 좌표축, 최신 계획 경로를 표시하는 것을 확인했다. RViz가 늦게 구독해도 최신 경로를 수신하고, 재계획 시 화면에 경로를 갱신한다.

지도 창을 켠 (16,12) 실행은 공식 referee PASS, 골반 거리 0.161m, 미션 시간 13.45초, 자체 done이었다. [공식 결과](../results/run_20261127-123547.json). 이 GUI 검사는 RViz를 표시하고 시뮬레이터의 RGB/Panda 렌더링은 끈 상태로 진행했다. 종료 시 RViz와 주행 노드도 정상 종료했다.

`--headless`와 `--no-map`의 지도 창 비활성화 전달 및 chapter별 launch 조건을 확인했다. 지도 화면은 기본 활성화이며 별도 인자 없이 기존 좌표 입력 명령으로 열린다.

## 환경과 검증 범위

- ROS 2 Humble, Python 3.10, MuJoCo 3.7.0, onnxruntime 1.23.2, 제공 G1 보행 ONNX.
- 공식 `main.py --missions 1`과 원본 referee 사용. 별도 ROS 도메인 74/75에서 실행했다.
- headless 시험은 RGB/Panda 렌더링을 끄고 LiDAR 10Hz, IMU 100Hz, sensor TF와 보행을 실행했다.
- 저장 지도·수동 initialpose·GT odometry 옵션 없이 시작했다. 공개 최초 위치와 첫 센서 odometry TF로 초기화했다.
- 관측된 공간의 경로 계획, 이동 중 지도 갱신, 바닥 센서 추정, 정지 상태 확인을 거쳤다. 공식 성공 반경은 0.5m, 자체 목표 반경은 0.20m다.
- 센서보다 늦는 TF가 최신 스캔에 계속 밀려 처리되지 않던 문제에 대해 최근 관측 큐를 추가했다. 변환 가능한 최신 관측을 선택하며 stale 센서로 계속 주행하지 않는다.
- 복도 방향의 스캔 간 이동량 편향을 줄이기 위해 odometry에 point-to-line 정합을 적용했다. 평행 벽만 있어 이동을 관측할 수 없는 경우에는 실패 처리한다.
- 제공 정책은 명령 크기 0.1 미만에서 보행 위상을 멈추므로 목표 접근 중 전진 속도를 0.11m/s 이상으로 유지하고, 목표 반경에서 정지한다.
- 모든 주행 노드는 종료 신호 뒤 정상 종료했다.

## 한계

테스트한 세 목표의 결과이며 모든 좌표·상황의 PASS 보증은 아니다. 온라인 지도는 loop closure 없는 센서 odometry에 의존한다. 긴 이동·대칭 구조·새 장애물·센서 지연에서는 실패할 수 있다. 실제 리스폰 후 재주행은 이번 주행 시험에 포함하지 않았으며 공개 이벤트 순서·epoch 변경·동일 목표 재계획은 프로토콜 검사로 확인했다.

최종 룰북의 로컬 LLM과 팀이 학습한 humanoid 정책 요구는 이 좌표 입력 연습의 검증 대상에 포함하지 않는다. 특히 제공 ONNX로 한 주행 성공을 팀 정책 학습 요구를 충족한 것으로 표시하지 않는다. 팀 모델을 준비하면 `custom/robot.yaml`로 연결하고 다시 검증해야 한다.
